# Checkup Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Settings tab, Checkup, that checks live whether the project has everything Gyroscope needs, grouped, with a refresh icon and a Fix link per failing check.

**Architecture:** A pure table parser (`src/checkup/tables.ts`) reads the Metrics tables out of the descriptions. A runner (`src/checkup/run.ts`) fetches what it needs through `OwoxLike`, reuses the existing graph and health code, and reports the whole check list through `onUpdate` each time a check changes. `CheckupTab` renders that list; `SettingsPage` and `App` add the tab and the route.

**Tech Stack:** React 18, TypeScript, Vitest + Testing Library, lucide-react.

**Spec:** `docs/superpowers/specs/2026-11-04-checkup-design.md`. Read it first; its Checks table is the source of every check's label, status and fix.

## Global Constraints

- Run tests with `npx vitest run --maxWorkers=4` only (this machine overheats otherwise). Keep `npx tsc --noEmit -p .` clean.
- No new dependencies. No AI call. No storage writes. `plugin.json` doesn't change.
- Use only the CSS tokens in `src/styles.css`, in light and dark. Visible keyboard focus (`outline: none; box-shadow: 0 0 0 2px var(--primary)`). Every control has an accessible name.
- UI text in sentence case, straight quotes, no em dashes.
- Match the surrounding code: dense one-line helpers, short `//` comments only where the reason isn't obvious, `/** */` on exported functions.
- Commit after each task. Message style: `feat: <what the user gets>`, ending with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A refresh clicked while a run is still going: the old run's late updates must not overwrite the new run's list. Test in Task 3.
2. A description with a table that has Role/Plan/Fact columns but no Metric column, or extra columns, or cells with escaped pipes is rare; a table without a separator row is not a table. Tests in Task 1.
3. `/api/contexts` refused (`contextsOk: false`): the Contexts group fails its "contexts exist" check with "Contexts couldn't be read", and the "matches the descriptions" check is skipped, not reported as out of date. Test in Task 2.
4. The goal Data Mart isn't accessible to the member but another Data Mart references it: the Goal group fails "published and you can access it", and Connections still passes "goal is reachable". Test in Task 2.
5. One Data Mart's schema request fails while others succeed: only checks about that Data Mart fail; the run finishes. Test in Task 2.

Parsing rules (from the spec): a table is a header row of `|`-separated cells followed by a separator row (cells of `-`, `:` and spaces only). It's a Metrics table when the header cells, trimmed and lowercased, include `role`, `plan` and `fact`. `metric` is the cell under a `metric` column, else the label (`text`) of the first Fact link, else `''`. The table ends at the first line that doesn't start with `|` (after trimming). Leading and trailing `|` are optional. An escaped pipe `\|` stays inside its cell.

- [ ] **Step 3: Write `src/checkup/types.ts`** exactly as in Interfaces, and `src/checkup/tables.ts`:

```ts
import { extractLinks, type MartLink } from '../lib/links';

export interface MetricRow { role: string; metric: string; plan: MartLink[]; fact: MartLink[] }

// splits a table line into cells; `\|` stays inside its cell
const cells = (line: string): string[] => {
  const t = line.trim().replace(/^\|/, '').replace(/(?<!\\)\|$/, '');
  return t.split(/(?<!\\)\|/).map((c) => c.trim().replace(/\\\|/g, '|'));
};
const isSeparator = (line: string) => /^\|?\s*:?-+:?\s*(\|\s*:?-+:?\s*)*\|?$/.test(line.trim());

/** Every body row of every Metrics table in the Markdown, in order. */
export function findMetricRows(markdown: string | null | undefined, source: 'project' | string): MetricRow[] {
  if (!markdown) return [];
  const lines = markdown.split(/\r?\n/);
  const out: MetricRow[] = [];
  for (let i = 0; i + 1 < lines.length; i++) {
    if (!lines[i]!.includes('|') || !isSeparator(lines[i + 1]!)) continue;
    const head = cells(lines[i]!).map((c) => c.toLowerCase());
    const [role, plan, fact, metric] = ['role', 'plan', 'fact', 'metric'].map((n) => head.indexOf(n));
    if (role! < 0 || plan! < 0 || fact! < 0) continue;
    let j = i + 2;
    for (; j < lines.length && lines[j]!.trim().startsWith('|') || (j < lines.length && j === i + 2 && lines[j]!.includes('|')); j++) {
      const row = cells(lines[j]!);
      const factLinks = extractLinks(row[fact!] ?? '', source, 0);
      out.push({
        role: row[role!] ?? '',
        metric: (metric! >= 0 ? row[metric!] : undefined) || factLinks[0]?.text || '',
        plan: extractLinks(row[plan!] ?? '', source, 0),
        fact: factLinks,
      });
    }
    i = j - 1;
  }
  return out;
}
```

The loop condition above is hard to read; write it as a `while` with a helper `isRow(line, first)` that accepts any line with `|` that starts with `|`, or, for a table whose header had no leading `|`, any line containing `|`. Track `leading = lines[i].trim().startsWith('|')` from the header and require body rows to match it (a header without a leading pipe takes body rows that contain `|` and aren't blank). Then:

```ts
/** The first row whose role contains "critical", any case. */
export const criticalRow = (rows: MetricRow[]): MetricRow | null => rows.find((r) => /critical/i.test(r.role)) ?? null;
/** A link that names a real Data Mart field: not a placeholder, with a Data Mart id and a field. */
export const isFieldLink = (l: MartLink): boolean => !l.placeholder && !!l.martId && !!l.field;
```

  owox: OwoxLike; hasAi: boolean; model: Model | null; projectId: string;
  /** The whole list, each time a check changes. */
  onUpdate: (checks: Check[]) => void;
}

**Behaviour.** Keep a `Map<string, Check>` in insertion order and a `set(check)` that writes and calls `onUpdate([...map.values()])`. First publish every fixed check as `running` (Plugin, Project, Goal, Contexts "exist", Connections, Saved model) so the tab draws the whole list at once. Then:

1. `plugin.ai`: `ok` when `hasAi`, else `fail` "No AI credential is mapped to Gyroscope", fix `{ kind: 'owox', label: 'Plugins', path: '/ui/{projectId}/plugins' }`.
2. `fetchInputs(owox)`. If it throws, every remaining `running` check becomes `fail` with detail `Couldn't read the project: <describeError>` and the run ends.
3. Project group (fix `Project settings` → `/ui/{projectId}/project-settings`):
   1. `project.description`: `fail` "The project description is empty" when blank.
   2. `project.table`: `fail` "No Metrics table with Role, Plan and Fact columns" when `findMetricRows(desc,'project')` is empty; its fix is `{ kind: 'snippet', label: 'Copy a Metrics table' }`.
   3. `project.critical`: `fail` "No Critical number row" when `criticalRow` is null; `ok` detail = the row's metric.
   4. `project.fact`: `fail` "The Critical number's Fact doesn't link a Data Mart field" unless its first Fact link `isFieldLink`. `ok` detail `<metric> (<mart title from inputs.marts, or the link text>)`.
   5. `project.plan`: `warn` "No plan: the goal shows without one" unless a Plan link `isFieldLink`.
   6. `project.links`: see "Linked fields" below, over all links of the project rows.
   Each check after a failed one it depends on is `skip` with detail `Needs: <label of that check>` (table needs description, critical needs table, fact and plan need critical).
4. Goal group: needs `project.fact` ok, else all four `skip`. Goal id = the fact link's `martId`, field = its `field`. Fix: `{ kind: 'owox', label: 'Open <title>', path: '/ui/{projectId}/data-marts/{id}/data-setup' }`.
   1. `goal.access`: `fail` "Not published, or you can't access it" when the id isn't in `inputs.marts` (that list is already filtered to published and reportable). When it fails, the other three are `skip`.
   2. Fetch its detail with `fetchMartDetail`; on error the three are `fail` with the error.
   3. `goal.field`: `fail` "Field <field> isn't in <title>" when not in `allFieldPaths(detail.fields)`.
   4. `goal.pk`: `fail` "No primary key: it can't be a class" unless `hasPrimaryKey(detail)`.
   5. `goal.date`: `fail` "No date field" unless some `flattenFields` entry has a type in `DATE_TYPES` (compare uppercased).
5. Contexts group (fix `Contexts` → `/ui/{projectId}/contexts`):
   1. `contexts.exist`: `fail` "Contexts couldn't be read" when `!inputs.contextsOk`; `warn` "No contexts" when the list is empty; else `ok` detail "<n> contexts".
   2. For each context `c`, with `context: { id, name }`: `context:<id>.description` (`warn` "Empty description"); `context:<id>.marts` (`warn` "No Data Marts in this context", counted as `inputs.marts.filter(m => m.contexts.some(x => x.id === c.id))`; ok detail "<n> Data Marts"); `context:<id>.fact` (`warn` "No metric row links a fact" unless any row of `findMetricRows(c.description, c.id)` has a fact link that `isFieldLink`); `context:<id>.plan` (same for plan, "No metric row links a plan"); `context:<id>.links` (Linked fields below). Publish these as `running` right after the inputs load.
6. Linked fields (used by `project.links` and each `context:<id>.links`): every `isFieldLink` link of the rows' Plan and Fact cells. A link whose `martId` isn't in `inputs.marts` is missing: "<text>: Data Mart not found or not accessible". Otherwise its `field` must be in `allFieldPaths` of that Data Mart's detail: "<text>: field <field> isn't in <title>". `fail` with the problems joined by `; `, `ok` detail "<n> links" when none (`ok` "No links" when there are no links). A detail fetch that fails makes that link a problem "<text>: <describeError>".
7. Connections group. Load every Data Mart in `inputs.marts` into `MartNode`s (detail + blendable), 6 at a time with `runPool`; reuse details already fetched. A failed one is left out. `visible = ids of inputs.marts`. Needs `project.fact` ok, else all `skip`.
   1. `edges = buildEdges(nodes, visible, goalId)`.
   2. `connections.reachable`: `main = chooseMain({ goalMartId: goalId, goalField, nodes, visible })`. `fail` "No Data Mart you can access references the goal's Data Mart through a calculated field" when null (fix: the goal's Data Mart). `ok` detail = "You can access <title>" or "Through <from title>" when `viaFallback`.
   3. `connections.any`: `warn` "No calculated field references another Data Mart" (fix `{ owox, 'Data Marts', '/ui/{projectId}/data-marts' }`) when `edges` is empty; `ok` detail "<n> connections".
   4. `connections.facts`: `depths = classDepths(main.id, edges, withPk)` where `withPk` = ids of nodes with `hasPrimaryKey`. The fact-linked Data Marts are the `martId`s of every `isFieldLink` Fact link of the project and context rows that are in `visible`. `warn` "Not connected to the goal, so not on the canvas: <titles>" for those not in `depths` (fix: the first one's Data Mart page). Skip when `reachable` failed.
   5. `connections.pk`: `warn` "No primary key: <titles>" for fact-linked Data Marts whose node lacks a primary key (fix: the first one's page).
8. Saved model group. With `model === null`, both `skip` "No model built yet". Else:
   1. `model.health`: `checkHealth(owox, model, visible)`; `warn` "<n> broken references" (singular "1 broken reference") with fix `{ kind: 'tab', label: 'Open Metrics', tab: 'ontology' }`; `ok` otherwise.
   2. `model.fresh`: `skip` "Contexts couldn't be read" when `!inputs.contextsOk`. Else `currentInputHash(owox, inputs, model.classes.map(c => c.id), detailsMap)`; `warn` "The descriptions changed since the model was built" (same tab fix) when it differs from `model.inputHash`; a thrown error is `fail` with it.

Wrap each group in try/catch so one failure marks only that group's still-running checks `fail` with the error. Run groups 5 to 8 concurrently after the inputs load (`Promise.all`); the goal detail and context link details go through one shared `detail(id)` memo (`Map<string, Promise<MartDetail>>`) so a Data Mart is fetched once per run.
